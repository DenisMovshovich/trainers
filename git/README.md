# Git — интерактивный курс контроля версий

12 разделов теории, 72 вопроса, 26 заданий со 112 автоматическими проверками
и 21 разбор вопросов с собеседований. Команды выполняет встроенный git
на JavaScript — без сети, без установки и без риска что-нибудь сломать.

## Файлы

| Файл | Что это |
|---|---|
| `git.html` | исходник артефакта (без `<!doctype>`, `<html>`, `<head>`, `<body>` — их добавляет публикатор) |
| `git-offline.html` | автономная копия: открывается двойным щелчком из Finder |
| `src/` | исходные части и сценарии сборки и проверки |

## Разделы

1. Три дерева — рабочая копия, индекс, HEAD; чтение `git status`, отмена на каждом уровне
2. Коммит — что в нём лежит, `--amend`, `-a`, ловушка `.gitignore` с отслеживаемым файлом
3. Объекты — blob, tree, commit, tag; адресация по содержимому и неизменяемость истории
4. Ветки — указатели и HEAD, detached HEAD, `switch` против `checkout`, обращение к коммитам
5. Слияние — fast-forward и `--no-ff`, база слияния, конфликты, `--abort`, `ours`/`theirs`
6. Перебазирование — обычное и интерактивное, золотое правило, `--onto`
7. Отмена — `reset` во всех режимах, `revert`, `restore`, отмена коммита слияния
8. Спасение — reflog, `ORIG_HEAD`, `fsck`, stash и почему коммит лучше него
9. Сервер — `origin/main` как снимок, `fetch` против `pull`, отслеживаемые ветки, `prune`
10. В команде — отклонённый push, `pull --rebase`, `--force-with-lease`, восстановление затёртого
11. Поиск — фильтры лога, `blame`, `log -S`, двоичный поиск `bisect`, диапазоны
12. Практики — pull request и три кнопки слияния, стратегии ветвления, что настроить один раз

## Что умеет движок

Хранилище объектов с адресацией по содержимому: одинаковое содержимое даёт один blob,
каталоги — настоящие вложенные деревья, хеш коммита включает родителя. Индекс отдельно
от рабочей копии. Ветки, метки (лёгкие и аннотированные), reflog на каждую ссылку.
Трёхстороннее слияние по строкам с настоящими маркерами конфликта, перебазирование
с планом (`pick`, `reword`, `squash`, `fixup`, `drop` и перестановка), `reset` в трёх
режимах, `revert` включая коммиты слияния, `cherry-pick`, `stash`, `bisect`, `blame`,
`log -S` и диапазоны `A..B`. Отдельный репозиторий на роли сервера: `fetch`, `push`,
`pull --rebase`, отслеживаемые ветки, отказ при расхождении и проверка `--force-with-lease`.
Есть немного оболочки — `echo`, `cat`, `ls`, `rm`, `touch`, — чтобы было чем создавать файлы;
многострочные правки удобнее делать в редакторе файла внизу.

Сознательно **не** реализованы: подмодули, worktree, хуки, подписи, разреженная выгрузка,
упаковка объектов и сеть; хеш — не SHA-1, хотя ведёт себя так же.

Поведение воспроизводит настоящий git там, где на этом учатся: коммит собирается
из индекса, а не из рабочей копии; `.gitignore` не действует на уже отслеживаемые файлы;
перемотка отличается от коммита слияния; перебазирование меняет хеши; изменение коллекции
веток видно в reflog; `fsck` молчит, пока на коммит ссылается reflog; push отклоняется
при расхождении, а `--force-with-lease` ловит чужой коммит.

## Сборка и проверка

```sh
cd src
./assemble.sh   # собирает оба HTML
./verify.sh     # полная проверка
```

`verify.sh` последовательно выполняет:

1. **движок** — `runt.sh`: 73 теста на поведение git;
2. **эталонные решения** — `check.js`: прогоняет решения ко всем 26 заданиям
   на их сценариях, должно быть 112 / 112;
3. **негативный контроль** — `check.js --neg`: на нетронутом сценарии не должна
   пройти ни одна проверка, ожидается 0 / 112;
4. **целостность** — `integrity.js`: разделы и вопросы, баланс HTML-тегов, отсутствие
   посторонних тегов в примерах, построение всех 26 сценариев и разбор всех 46 примеров
   из нижней панели;
5. **сборка** обоих файлов;
6. **браузер** — `browser.mjs`: Chromium, 5 сочетаний темы и ширины
   (1540 / 1120 / 820 / 390 px, светлая и тёмная). Кроме ошибок консоли и перелива
   проверяет живые сценарии: коммит в песочнице, конфликт слияния с правкой файла
   в редакторе и его завершение, интерактивное перебазирование через план —
   и что задания 1a, 5b и 6b после этого засчитываются;
7. **раскладка** — `fit.mjs`: правая колонка не уходит под терминал на шести
   высотах окна.

## Оформление

Палитра «граф»: чернильно-синий `#12161F` / светлая `#EEF0F3`, акцент — оранжевый
`#C2410C` (цвет git), синий для хешей и зелёный с красным для диффов.
Гарнитуры: Bitter (заголовки), IBM Plex Sans (текст), IBM Plex Mono (терминал).
Слева терминал, справа обозреватель репозитория: граф истории по всем веткам
и рабочая копия с пометками состояния. Нижняя панель переключается между терминалом,
редактором файла и планом перебазирования.
Тема следует системной, переключается кнопкой и запоминается.
Прогресс хранится в `localStorage` под ключом `git.v1`.
