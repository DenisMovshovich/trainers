# .NET

Интерактивный конспект по работе с .NET-проектами **и подготовка к собеседованию на
Automation QA**. 20 разделов, 111 вопросов самопроверки, 28 разборов вопросов с интервью,
разборы шести реальных файлов и пять конструкторов. Всё привязано к репозиторию
`Acme.WebAutomation` (Playwright + NUnit, .NET 8, три проекта в одном решении).

## Как открыть

* **Локально:** `dotnet-offline.html` — полноценный документ, открывается двойным щелчком.
Прогресс самопроверок хранится в localStorage, отдельно для каждого варианта открытия.
Интернет нужен только для шрифтов Google Fonts.

## Слой подготовки к собеседованию

В восемнадцати разделах из двадцати есть блок **«На собеседовании»**: вопрос →
что на самом деле проверяют → модельный ответ → какие уточняющие вопросы последуют.
Всего 28 карточек. Ответы написаны так, чтобы их можно было произнести вслух,
и опираются на измеренные факты этого репозитория, а не на общие слова.

Отдельно разобран **чужой тест с восемью изъянами** — самая частая практическая
задача на интервью, — и собраны формулировки для разговора о слабых местах
собственного проекта.

## Чем проверены факты

Числа и сообщения об ошибках не взяты из документации — они измерены на копии репозитория
живым SDK 10.0.302:

* `dotnet build` проекта на `net8.0` проходит на SDK 10 — пакет таргетинга приезжает из NuGet;
* 6 прямых пакетов → 23 разрешённых → 15 в `deps.json`;
* обнаружено тестовых случаев: Portal 249, Vertex2025 285, HQ 3;
* `--list-tests` **игнорирует** `--filter` — с фильтром и без него список одинаковый;
* тексты `NETSDK1004`, `NETSDK1045`, ошибки global.json воспроизведены и записаны дословно.

Для разделов 13–20 репозиторий пересчитан заново — Portal, Vertex2025 и HQ,
46 файлов, 11 025 строк:

| Измерено | Значение |
|---|---|
| `WaitForTimeoutAsync` — жёсткие ожидания | **284** (Vertex2025 278, Portal 6) |
| `[Retry]` | **38** — все в Portal, в Vertex2025 ни одного |
| Локаторы: XPath / CSS / `GetByRole` / `GetByTestId` | **178 / 188 / 114 / 0** |
| `Assert.That` против классических утверждений | **442 / 0** — к переходу на NUnit 4 готовы |
| `Expect(...)` Playwright | **544** |
| `[Parallelizable]` | **0** — прогон последовательный |
| `[TestCase]` / `[TestCaseSource]` | **0 / 1** на 432 тестовых метода |
| Пакеты во всех трёх проектах | NUnit **3.14.0**, Playwright.NUnit **1.58.0**, NUnit3TestAdapter **4.5.0** |

Эти числа и есть материал для ответа на вопрос «что бы вы улучшили в своём проекте»:
проблема названа, измерена, механизм понятен.

Два расхождения с документацией репозитория, найденные попутно:
`README.md` и `CLAUDE.md` называют для Vertex2025 294 теста, фактически 285;
`NumberOfTestWorkers=4` в runsettings, вероятно, ни на что не влияет — атрибута
`[Parallelizable]` в исходниках нет, а без него NUnit не распараллеливает.

## Проверка после правок

```sh
cd src
{ tail -n +2 30_data_a.js; cat 31_data_b.js 32_data_c.js 33_data_d.js; } > /tmp/d.js
node -e "$(cat /tmp/d.js); \
  let bad=0; \
  SECTIONS.forEach(s=>{const c=(s.body.match(/<code[ >]/g)||[]).length, z=(s.body.match(/<\/code>/g)||[]).length; \
    if(c!==z){console.log('раздел '+s.n+': code '+c+'/'+z); bad++;}}); \
  console.log(bad?'ПРОБЛЕМЫ':'теги сбалансированы')"
```

Незакрытый инлайн-тег в тексте раздела растягивает страницу по горизонтали и внешне
выглядит как поломка вёрстки — эта проверка ловит именно такой случай.
