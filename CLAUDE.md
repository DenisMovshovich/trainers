# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Восемь самодостаточных интерактивных учебных материалов. Каждый — **один HTML-файл**
без зависимостей: теория, вопросы, задания и работающий эмулятор внутри. Собирается
из пронумерованных частей конкатенацией, без сборщиков и без npm-проекта.

Материалы и их эмуляторы: `docker` (движок Docker), `rest` (HTTP-сервер),
`bash` (интерпретатор оболочки), `sql` (движок PostgreSQL),
`kafka` (кластер Kafka), `testing` (калькуляторы тест-дизайна),
`dotnet` (конспект .NET + собеседование), `anatomy` (разбор кода по
извлечённой модели).

## Команды

Имена скриптов сборки **не унифицированы** — проверяйте, какой есть:

```sh
cd <материал>/src && ./assemble.sh   # rest, bash, sql, kafka, testing
cd <материал>/src && ./build.sh      # docker, dotnet
cd anatomy/src/build && ./assemble.sh
```

Полная проверка одного материала (есть у `rest`, `bash`, `sql`,
`kafka`, `testing`):

```sh
cd <материал>/src && ./verify.sh
```

Отдельные шаги — так же запускаются поодиночке:

```sh
./runt.sh              # тесты движка (конкатенирует 3x_*.js + _t.js и гонит через node)
node check.js          # эталонные решения заданий: должно быть 100%
node check.js --neg    # негативный контроль: должно быть 0%
node integrity.js      # целостность содержания, баланс HTML-тегов, текст SVG внутри viewBox
node browser.mjs       # Chromium: все модули × вкладки × ширины × темы
node fit.mjs           # раскладка не уезжает под липкие панели
```

Всё разом плюс пересборка сайта:

```sh
./tools/verify-all.sh
```

Сайт (`docs/` — **результат сборки, в git не хранится**):

```sh
./tools/build-site.sh          # пересобрать материалы и сайт
./tools/build-site.sh --fast   # только сайт
cd docs && python3 -m http.server 8000
```

Браузерные проверки требуют `playwright-core`; пути не зашиты:

```sh
npm i -D playwright-core && npx playwright install chromium
# либо переопределить:
PLAYWRIGHT_CORE=/путь/к/playwright-core/index.mjs CHROMIUM_PATH=/путь/к/chrome-headless-shell node src/browser.mjs
```

## Архитектура

### Два выхода из одних исходников

Скрипт сборки всегда пишет **два** файла:

* `<имя>.html` — фрагмент **без** `<!doctype>`, `<html>`, `<head>`, `<body>`.
  Это формат для публикации артефактом: обёртку добавляет публикатор.
  Открытый напрямую, он уходит в quirks-режим и угадывает кодировку.
* `<имя>-offline.html` — то же плюс обёртка с `charset=utf-8`. Это то, что открывают
  и что попадает на сайт.

Правьте только `src/`. Оба HTML — производные.

### Порядок частей

Файлы конкатенируются по возрастанию номера, поэтому номер задаёт порядок исполнения:

```
10_head.html   <title>, шрифты, весь CSS
20_body.html   разметка-скелет
3x_*.js        движок эмулятора (начинается с <script>)
4x_content_*.js  содержание: массив модулей
5x_app.js      UI: рендер, прогресс, обработчики (заканчивается </script>)
```

`3x` и `4x` не оборачиваются в `<script>` сами — тег открывает первый файл движка,
закрывает `5x_app.js`. Из-за этого файл содержания синтаксически валиден только
в составе сборки; проверять его отдельно нужно так:

```sh
{ cat 4?_content_*.js; echo "];"; } > /tmp/c.js && node --check /tmp/c.js
```

### Модель содержания

Массив называется `MODULES` везде, кроме `dotnet`, где он `SECTIONS`
и наполняется через `SECTIONS.push(...)` из нескольких файлов.

```js
{ n, id, title, sub, lede,
  theory: `…HTML…`,          // в dotnet поле называется body
  quiz: [{q, opts:[4], a, why}],
  labs: [{id, title, brief, hint, ex, checks:[{label, test}]}],
  iv:   [{q, probe, a, more:[]}]   // «На собеседовании» — есть у testing и dotnet
}
```

**`id` разделов должны быть уникальны** — по ним идут поиск и переходы.

**Проверки заданий — функции над состоянием.** `check.test(st)` получает состояние
и возвращает булево. Что такое `st`, зависит от материала:

* эмуляторы с консолью (`docker`, `rest`, `bash`, `sql`, `kafka`) — `{db|c|fs, log}`,
  где `log` хранит выполненные команды и их результаты; проверки смотрят на **результат**,
  а не на текст команды;
* `testing` — `{ans, tools}`: ответы виджетов (`values`, `classify`, `pick`, `fields`).

**`sol.js` — эталонные ответы** к каждому заданию, `check.js` прогоняет их и требует
100%. У `kafka` задания идут по **общему накапливающемуся** кластеру,
поэтому решения выполняются последовательно, а проверки — сразу после своего задания.

### Как проверяется качество

Порядок в `verify.sh` не случаен и его стоит сохранять:

1. **тесты движка** — семантика эмулятора отдельно от содержания;
2. **эталонные решения** — 100% проверок проходит;
3. **негативный контроль** — на пустом состоянии проходит **0%**. Ловит проверки,
   истинные «даром» (например `every(...)` по пустому выбору);
4. **целостность** — 4 разных варианта у каждого вопроса, корректный индекс ответа,
   баланс HTML-тегов во **всех** строках содержания, подписи SVG внутри `viewBox`;
5. **сборка**;
6. **браузер** — ошибки консоли и горизонтальный перелив на каждом модуле и вкладке.

## Что ломается и не ловится `node --check`

* **Незакрытый инлайновый тег** внутри шаблонной строки съедает следующий текст
  и рвёт ширину страницы. Для этого в `integrity.js` есть проверка баланса тегов.
* **`${` и обратные кавычки** внутри шаблонной строки нужно экранировать.
* **Класс с `display` перебивает атрибут `[hidden]`** — панели вкладок и инструментов
  показываются все разом. Лечится глобальным `[hidden]{display:none!important}`.
* **`1fr` в grid** даёт перелив страницы; нужен `minmax(0,1fr)`.
* **Липкие шапка и нижняя панель** вместе съедают вьюпорт, и элементы между ними
  становятся некликабельными. Проверяется отдельно `fit.mjs`.
* **Перемешивание вариантов ответа**: LCG вида `s*1103515245` без `Math.imul` теряет
  младшие биты, и верный ответ садится в одни и те же позиции. Нужны `Math.imul`
  и старшие биты (`s >>> 15`).
* **`\w` в регулярках** не покрывает кириллицу.

## Ограничения, которые нельзя нарушать

* **Никаких данных заказчика.** `anatomy` и `dotnet` обезличены:
  вымышленные `Acme.WebAutomation.*`, домены `*.example.com`, задачи `TC-####`.
  Возвращать настоящие имена, внутренние хосты или идентификаторы задач нельзя.
  Оригиналы лежат вне репозитория.
* **Никаких абсолютных путей** в скриптах — ни `/Users/...`, ни имени пользователя.
  Файлы ищутся относительно скрипта, браузер — через `PLAYWRIGHT_CORE` и `CHROMIUM_PATH`.
* **`docs/` не коммитится** — собирается из исходников workflow'ом `.github/workflows/pages.yml`.
* Единственная внешняя зависимость страниц — шрифты Google Fonts. Ничего больше
  подгружать нельзя: материалы должны работать без сети.

## Стиль текста

Материалы написаны по-русски, включая имена в коде содержания. Тон — объясняющий,
без канцелярита и маркетинга; факты о репозитории-примере даются измеренными числами.
Держитесь этого при правках.
