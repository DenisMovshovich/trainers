# REST

Интерактивный тренажёр по REST: теория, тесты и практика на эмуляторе HTTP-сервера.
Запросы выполняются по-настоящему — состояние сервера меняется, а обмен виден в сыром виде HTTP.

* **Локально:** `rest-offline.html` — открывается двойным щелчком.

## Эмулятор

Внутри — работающий REST-сервер `api.example.com` с ресурсами `/users`, `/posts`, `/orders`
и `/auth/token`. Реализованы: семь методов, фильтрация, сортировка, пагинация с `Link` и
`X-Total-Count`, согласование содержимого, Bearer-токены с областями доступа, валидация с
`problem+json`, `ETag` с условными чтением и записью, `Idempotency-Key`, ограничение частоты
с `Retry-After`, редирект `301`.

Ввод — в стиле curl или коротко:

```
GET /users?limit=2&page=2
POST /auth/token -H 'Content-Type: application/json' -d '{"username":"demo","password":"secret"}'
PATCH /users/1 -H 'Content-Type: application/json' -H 'Authorization: Bearer tok_…' -H 'If-Match: "u1-v1"' -d '{"role":"user"}'
```

Учётные данные: `demo` / `secret`. Область доступа задаётся полем `scope` в теле запроса токена.

## Проверка

```sh
cd src && ./verify.sh
```

* **49 тестов эмулятора** — семантика методов, кодов, заголовков и условных запросов.

## Решение, которое стоит помнить

Сервер отвечает **405 раньше 401**: допустимость метода — свойство ресурса, а не вызывающего.
Это позволяет изучать `405` и заголовок `Allow`, не получая сначала токен, и не раскрывает
требования к авторизации для методов, которых у ресурса нет вовсе.
