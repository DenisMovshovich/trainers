# Ubuntu Server

Интерактивный курс администрирования Linux на примере Ubuntu Server.
Один HTML-файл: теория, вопросы, задания и работающая модель системы внутри.

Открывать `ubuntu-offline.html`. Файл `ubuntu.html` рядом — фрагмент для встраивания,
в браузере он открывается неправильно.

## Что внутри

12 разделов, 72 вопроса, 24 задания со 162 автоматическими проверками
и 24 разбора вопросов с собеседований.

## Модель системы

Команды выполняет не заглушка, а модель на JavaScript:

* **файловая система** — узлы с режимом, владельцем и группой; проверка прав по первому
  подходящему набору; символьные ссылки; setuid, setgid и липкий бит; umask;
* **оболочка** — кавычки и подстановки, конвейеры, перенаправления `> >> < 2> 2>&1`,
  `&&`, `||`, шаблоны имён, коды возврата, исполняемые сценарии;
* **учётные записи** — passwd, group, shadow, основная и дополнительные группы,
  sudo с проверкой группы и правил из `/etc/sudoers.d`;
* **systemd** — разбор unit-файлов, `daemon-reload`, start против enable, `Restart=`,
  журнал с уровнями и загрузками;
* **пакеты** — репозиторий с версиями и зависимостями, apt и dpkg, службы и файлы,
  которые пакет приносит и уносит;
* **процессы** — `ps`, `top`, сигналы, перезапуск службы по `Restart=`;
* **диски** — разделы, UUID, `fstab`, `mount -a`, inode;
* **сеть** — `ip`, `ss`, netplan с разбором YAML, ufw, sshd с проверкой прав на ключи;
* **расписание** — crontab с проверкой формата, таймеры systemd.

Модель намеренно ошибается там же, где ошибается настоящая система: перенаправление
выполняется до повышения прав, поэтому `sudo echo > /etc/файл` отказывает; удаление
файла зависит от прав на каталог; `systemctl start` не видит unit-файл до `daemon-reload`;
занятый порт валит запуск службы; sshd отказывается от ключа со слишком открытыми правами;
`ufw enable` без правила на 22-й порт отрезает доступ.

## Пересборка и проверка

```sh
cd src && ./assemble.sh    # собрать обе версии
cd src && ./verify.sh      # полный цикл проверок
```

`verify.sh` прогоняет тесты модели, эталонные решения всех заданий (должно быть 100%),
негативный контроль (на нетронутой машине должно быть 0%), целостность содержания,
сборку, браузерную проверку в Chromium и проверку раскладки.
