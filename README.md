# Тренажёры

Одиннадцать самодостаточных интерактивных материалов по инженерным темам.
Каждый — **один HTML-файл**: вся теория, все проверки и работающий эмулятор
внутри. Ни сборки, ни зависимостей, ни сервера — открывается двойным щелчком.

## Сайт
Все одиннадцать доступны по отдельным адресам как статический сайт:

```
/            титульная с карточками
/docker/  /rest/  /bash/  /sql/  /kafka/  /testing/
/git/  /k8s/  /csharp/  /dotnet/  /anatomy/
```

Каталог `docs/` — **результат сборки**, в репозитории он не хранится:
источник истины лежит в `<материал>/src/`. Так дубликаты не попадают
в историю, а сайт не может разойтись с содержимым исходников.

```sh
./tools/build-site.sh          # пересобрать материалы и сайт
./tools/build-site.sh --fast   # только сайт
cd docs && python3 -m http.server 8000   # посмотреть локально
```

Публикация на GitHub Pages идёт через Actions (`.github/workflows/pages.yml`):
при пуше в `main` сайт собирается из исходников и выкладывается.
В настройках репозитория нужно один раз выбрать **Settings → Pages → Source: GitHub Actions**.

## Что делает их не текстом

Внутри девяти из одиннадцати работает настоящий эмулятор, написанный на JavaScript:

* **Docker** — движок контейнеров: сборка образов, слои, кеш, тома, сети;
* **REST** — HTTP-сервер с маршрутизацией, кодами ответов и заголовками;
* **Bash** — интерпретатор оболочки: разбор, конвейеры, перенаправления, подстановки;
* **SQL** — движок PostgreSQL: соединения, оконные функции, транзакции, план запроса;
* **Kafka** — кластер из трёх брокеров: репликация, ISR, выборы лидера, смещения;
* **Тестирование** — калькуляторы техник тест-дизайна: границы, попарные наборы, аудит баг-репорта;
* **C#** — интерпретатор языка: классы и структуры, свойства, виртуальные методы, интерфейсы,
  LINQ с отложенным выполнением, исключения, `using`, `async`/`await` с планировщиком;
* **Git** — хранилище объектов с адресацией по содержимому, индекс, ветки, трёхстороннее
  слияние с настоящими конфликтами, интерактивное перебазирование, reflog, bisect
  и отдельный репозиторий на роли сервера;
* **Kubernetes** — кластер: разбор YAML, цикл согласования с контроллерами, планировщик
  с учётом ресурсов и ограничителей, kubelet с пробами, конечные точки Service по меткам
  и плавные обновления с откатом.

Задания проверяются по-настоящему: движок исполняет то, что вы написали,
и проверка смотрит на результат, а не на текст команды.

## Как открыть

Возьмите файл с суффиксом **`-offline`** — это полноценный документ.
Файл без суффикса рядом с ним — фрагмент без `<!doctype>` и `<head>`,
он существует только для встраивания и в браузере открывается неправильно.

Из сети подгружаются только шрифты Google Fonts. Без интернета всё работает,
просто подставляются системные шрифты. Прогресс хранится в `localStorage`
и не покидает устройство.

## Пересборка

У каждого материала есть `src/` с частями и скриптом сборки:

```sh
cd <материал>/src && ./assemble.sh   # либо ./build.sh
```

Скрипт собирает обе версии — фрагмент и автономный документ.

## Проверка

Там, где есть `verify.sh`, он прогоняет полный цикл: тесты движка,
эталонные решения заданий, негативный контроль, целостность содержания
и браузерную проверку в Chromium на нескольких размерах и в обеих темах.

```sh
npm i -D playwright-core && npx playwright install chromium
./tools/verify-all.sh          # все материалы подряд + сборка сайта
cd <материал>/src && ./verify.sh   # один материал
```

Браузер и путь к нему не зашиты в скрипты: берутся из `node_modules`,
при необходимости переопределяются переменными `PLAYWRIGHT_CORE` и `CHROMIUM_PATH`.

## Данные

Материалы `anatomy` и `dotnet` построены на архитектуре
реального рабочего проекта, но полностью обезличены: пространства имён,
адреса стендов и идентификаторы задач заменены на вымышленные
(`Acme.WebAutomation.*`, `*.example.com`, `TC-####`). Никаких данных
заказчика в репозитории нет.
